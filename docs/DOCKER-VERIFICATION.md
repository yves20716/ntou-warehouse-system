## 帳號與人員管理

以下檢查在兩種處理器架構的本機版與 HTTPS 部署版均通過。

| 檢查 | 實際結果 |
| --- | --- |
| 建立一般帳號 | 可建立客戶／倉儲帳號並綁定既有身分，初始狀態為待啟用 |
| 管理員限制 | 客戶與倉儲無法操作管理功能；網站無法建立或修改管理員，也不能改綁既有帳號 |
| 本人設定密碼 | 由主機發行連結，本人設定成功後啟用；管理頁沒有密碼雜湊或完整憑證 |
| 單次使用與重發 | 重發後舊連結失效；已用過的連結無法再用；同時送出只成功一次 |
| 到期及停用 | 過期憑證與停用帳號均拒絕設定密碼 |
| 既有登入 | 帳號停用、提出重設需求或重新發行連結後，原登入立即失效 |
| 員工離職 | 所屬帳號無法繼續登入，也不能替離職員工建立新帳號 |
| 管理紀錄 | 留下操作者與對象，事件內容沒有密碼或完整憑證；拒絕的升權操作不會新增帳號 |

## HTTPS 部署版

使用 `bin/production.sh` 與 `compose.production.yaml`，測試網域設為 `localhost`。Caddy 產生本機 CA，測試程式以該 CA 驗證 TLS 憑證與主機名稱。

- 初始化建立十一張空資料表，示範資料與帳號皆未載入。
- 依部署文件匯入基本資料範本，由 CLI 建立四個測試帳號；密碼隨機產生並僅供該次測試使用。
- 網站資料庫帳號降為 SELECT、INSERT、UPDATE、DELETE；實際嘗試建表會被拒絕。
- Apache 正常提供網站，HTTP 會轉到 HTTPS，登入 Cookie 有 Secure 屬性；設定檔、應用程式與 SQL 路徑回傳 404。
- 新帳號通過收發、權限、人員資料及重啟檢查。
- 依文件執行 `mysqldump`，另外寫入一筆測試資料，再還原備份；還原後十一表雜湊與備份前一致，網站也能重新登入查詢。
- 另建舊版八表資料庫，先套用申請表 migration，再套用帳號管理 migration；兩份都重跑一次，最後為十一張表。原有 6 筆進出貨與庫存總量 158 保留，`hr` 角色改為 `admin`，既有月薪維持 NULL。

## 重新執行測試

開啟 [Actions 頁面](https://github.com/yves20716/ntou-warehouse-system/actions/workflows/demo.yml)，選 **Run workflow**。有程式或設定變更時也會自動執行；只有 Markdown 文件修改時略過。

測試範圍為 Linux amd64／arm64 容器。Windows／macOS 的 Docker Desktop 安裝、公開網域 DNS 設定與憑證簽發尚未驗證。

本機安裝步驟見 [README](../README.md)；主機與網域設定見 [部署文件](DEPLOYMENT.md)。
