# 使用流程

先依 [README](../README.md) 在自己的電腦啟動，或登入管理者架設的 HTTPS 網站。下列範例以本機示範資料操作；正式安裝請改用自己建立的帳號與儲區。

## 誰負責哪些事情

| 身分 | 日常操作 | 權限範圍 |
| --- | --- | --- |
| 客戶 | 建立／編輯貨物、申請入庫或出庫、取消待處理申請、查看批次及紀錄 | 只限自己的公司 |
| 倉儲 | 貨物維護、受理客戶申請、現場直接收發、查詢全部批次 | 確認收發後才改變庫存 |
| 人資 | 員工新增、查詢、修改、刪除與主管設定 | 不操作收發或客戶資料 |

客戶公司、倉庫、儲區與租約由管理者在資料庫設定，目前不提供這些資料的管理頁面。網站不提供公開註冊，登入帳號由主機管理者建立。

## 一次完整收發

1. 用 `client` 登入，在「貨物品項」新增「展示用收納盒」，單位填「箱」。同一客戶不能建立同名貨物，另一家客戶可以使用相同名稱。
2. 從該品項提出入庫申請，填 10。此時「申請」會顯示待處理，但庫存不增加。
3. 登出，改用 `employee`。在待處理申請選「處理申請」，儲區選「基隆港倉／A-01」，確認入庫。只能選這家客戶承租的儲區。
4. 改回 `client`，在「庫存批次」看到 10 箱。開啟明細，可查到入庫時間與承辦人。
5. 從同一批次申請出庫 3 箱，再由 `employee` 確認出庫。餘量變成 7，明細保留入庫 10、出庫 3 兩筆紀錄。
6. 用 `client2` 登入，確認看不到前一家客戶的貨物、申請與紀錄。這個帳號代表另一家公司，不是管理員。

表格可搜尋、篩選及換頁。新增、編輯、申請及明細會開啟側邊面板；有未送出的修改時，關閉前會提示。送出後請看頁面的成功或錯誤訊息。

## 申請的四種結果

| 狀態 | 可以做什麼 | 對庫存的影響 |
| --- | --- | --- |
| 待處理 | 客戶取消；倉儲完成或填寫未受理原因 | 無 |
| 已完成 | 查詢處理時間、承辦人及進出貨紀錄 | 已寫入實際收發 |
| 未受理 | 查看原因，需要時另提新申請 | 無 |
| 已取消 | 保留供查詢，需要時另提新申請 | 無 |

出庫申請不會預扣或保留數量。即使送出時數量足夠，完成前也可能已被其他收發使用，因此倉儲確認時會再檢查餘量；不足時不會產生負庫存。重複點擊或重送已處理申請不會再扣一次。

## 現場收發與貨物修改

沒有客戶申請的現場作業，倉儲人員可直接登記入庫或出庫。每次入庫建立新批次；出庫選既有批次，數量必須大於 0 且不超過餘量。批次餘量與進出貨紀錄在同一筆交易內更新，寫入失敗會一併回復。

已有批次或入庫申請的貨物不能刪除，也不能任意改換客戶或計量單位，以免歷史紀錄改變意思。品名仍可修改。各貨物的單位可能不同，儲區容量目前只作參考，不是可直接加總的剩餘箱數。

## 人資操作

用 `hr` 登入可新增員工、修改職務與時薪、指定主管，也可查詢及刪除沒有其他資料引用的員工。員工不能當自己的主管，主管關係也不能繞回原員工。已有帳號、承辦紀錄、申請處理紀錄或部屬引用的員工會保留，刪除前會提示原因。

## 資料放在哪裡

本機 Docker 版把資料放在自己的 MySQL 命名資料卷；重啟服務會保留資料。下載 GitHub 只會拿到程式、建表檔和同一份虛構 seed，不會拿到其他人的即時庫存。

需要多人共同操作時，請依[部署說明](DEPLOYMENT.md) 架設一個共用的 HTTPS 網站。所有人連到同一服務才會讀寫同一個資料庫。備份、真實資料及登入密碼留在主機或私人備份位置，不上傳到公開儲存庫。
