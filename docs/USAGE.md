# 使用流程

先依 [README](../README.md) 在自己的電腦啟動，或登入管理者架設的 HTTPS 網站。下列範例以本機示範資料操作；正式安裝請改用自己建立的帳號與儲區。

## 角色與權限

| 身分 | 日常操作 | 權限範圍 |
| --- | --- | --- |
| 客戶 | 建立／編輯貨物、申請入庫或出庫、取消待處理申請、查看批次及紀錄 | 只限自己的公司 |
| 倉儲 | 貨物維護、受理客戶申請、現場直接收發、查詢全部批次 | 確認收發後才改變庫存 |
| 帳號與人員管理員 | 建立一般帳號、啟停帳號、提出重設需求、維護人員與查閱管理紀錄 | 不操作庫存與收發；網站不能建立或修改管理員帳號 |

客戶公司、倉庫、儲區與租約由管理者在資料庫設定，目前不提供這些資料的管理頁面。網站不提供公開註冊。管理員可替既有員工或客戶建立一般帳號；管理員帳號由主機管理者建立。

## 收發操作範例

1. 用 `client` 登入，在「貨物品項」新增「展示用收納盒」，單位填「箱」。同一客戶不能建立同名貨物，另一家客戶可以使用相同名稱。
2. 從該品項提出入庫申請，填 10。申請狀態為「待處理」，庫存維持不變。
3. 登出，改用 `employee`。在待處理申請選「處理申請」，儲區選「基隆港倉／A-01」，確認入庫。只能選這家客戶承租的儲區。
4. 改回 `client`，在「庫存批次」看到 10 箱。開啟明細，可查到入庫時間與承辦人。
5. 從同一批次申請出庫 3 箱，再由 `employee` 確認出庫。餘量變成 7，明細保留入庫 10、出庫 3 兩筆紀錄。
6. 用另一家客戶的帳號 `client2` 登入，檢查資料隔離：該帳號無法查閱前一家客戶的貨物、申請與紀錄。

表格可搜尋、篩選及換頁。新增、編輯、申請及明細會開啟側邊面板；有未儲存的修改時，關閉前會提示確認；送出後顯示處理結果。

## 申請狀態

| 狀態 | 可執行的操作 | 對庫存的影響 |
| --- | --- | --- |
| 待處理 | 客戶取消；倉儲完成或填寫未受理原因 | 無 |
| 已完成 | 查詢處理時間、承辦人及進出貨紀錄 | 已寫入實際收發 |
| 未受理 | 查看原因，需要時另提新申請 | 無 |
| 已取消 | 保留供查詢，需要時另提新申請 | 無 |

出庫申請不預扣或保留庫存。倉儲確認出庫時會重新檢查餘量，庫存不足或申請已處理時會拒絕操作。

## 現場收發與貨物修改

沒有客戶申請的現場作業，倉儲人員可直接登記入庫或出庫。每次入庫建立新批次；出庫選既有批次，數量必須大於 0 且不超過餘量。批次餘量與進出貨紀錄在同一筆交易內更新，寫入失敗會一併回復。

已有批次或入庫申請的貨物僅可修改品名，客戶與計量單位固定，且禁止刪除。儲區容量僅供參考，庫存依各貨物的計量單位分別記錄。

## 帳號與人員管理

用 `hr` 登入帳號與人員管理。管理員可查閱帳號、角色、所屬員工或客戶及啟用狀態。建立一般帳號時，先選「倉儲員工」或「客戶」，再綁定既有資料。帳號建立後先顯示「待啟用」，角色及對應的員工／客戶固定。主機管理者產生一次性連結並交給帳號本人，由本人設定密碼後啟用。連結有效 30 分鐘，使用一次即失效；重發會撤銷舊連結。詳細指令見[部署說明](DEPLOYMENT.md)。

網站管理員無法建立或修改其他管理員、調整自己的角色、代登入，也無法查看使用者密碼。管理頁面不提供收發、庫存修改或歷史紀錄刪除。

需要重設密碼時，由管理員提出重設需求，再由主機管理者產生一次性連結交給本人。網站管理員無法取得該連結。提出重設需求後，原登入失效，須完成新密碼設定才能再次登入。

停用帳號後，該帳號無法登入，原本的登入也會失效。員工離職時，所屬帳號同樣無法繼續操作；過去的承辦紀錄仍保留。

員工名冊可維護姓名、職務、主管及在職狀態；月薪放在人員詳細資料。全新示範資料使用虛構月薪；舊資料升級後先顯示「未設定」，由管理員填入。職務名稱僅作人事記錄，網站權限依帳號角色決定。主管不得是本人，主管關係也不得形成循環。沒有帳號、部屬或承辦紀錄引用的臨時員工可刪除。

帳號建立、啟停及重設需求會留下管理紀錄，可查到操作人、時間與對象。管理紀錄不保存密碼或一次性連結。

## 資料儲存與共用

本機 Docker 版將資料存放於 MySQL 命名資料卷，重啟服務會保留資料。各台電腦使用獨立資料庫，首次安裝時載入儲存庫提供的示範資料。

多人共同操作時，請依[部署說明](DEPLOYMENT.md) 架設 HTTPS 網站，讓使用者連線至同一個資料庫。備份、真實資料與登入密碼應保存在主機或私人備份位置，禁止上傳至公開儲存庫。
